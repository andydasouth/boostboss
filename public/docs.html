Docs/Getting started/Introduction

Boost Boss documentation

Boost Boss is an MCP-native launch network that runs context-aware sponsored content inside AI tools. Every AI dev is both sides of the network: host ads to earn Credits, spend Credits to promote your own product. Two roles share the same account model. Pick the one that matches what you're trying to do.

★ Start hereUpdated Jun 2026·4 min read

Which role are you?

Publisher

You run an AI app, MCP server, or bot

You have an audience using AI tools you build. Drop a Lumi SDK in, return context, and every hosted impression mints 1 Credit. Four installation paths — pick the one matching what you ship. Spend your Credits to promote your own product across the network.

Get started as a publisher Advertiser

You want to reach AI tool users

Upload your product and creatives, pick a goal — Benna handles allocation across all four AI surfaces. Fund campaigns with the Credits you earn hosting, or add cash to amplify. Direct boosts through SuperBoost or programmatic via the BBX OpenRTB exchange.

Get started as an advertiser

Both roles in one account

You sign in once. The dashboard exposes both sides — most devs start by installing an SDK to earn Credits, then spend those Credits promoting their own product; some start by adding cash to amplify first. The same Supabase user ID carries through, so your Credits balance, 2FA, and history follow you.

Common concepts

Every role touches the same primitives. Once these click, the surface area of any specific role is small.

Publisher ID
Every publisher account gets an ID like pub_xxx. Use it on every ad request — it's how Boost Boss attributes impressions and revenue.
Context signal
Publishers pass a context string with every ad request — the user's current intent, the tool being called, the page topic, whatever describes "what would be relevant right now." Benna (our ranker) uses it for contextual matching. No cross-site tracking, no behavioral profile.
Credits
The network's only currency for publishers. Every hosted impression mints 1 Credit. Credits are spent to promote your own product across the network — they are never converted to cash, and there are no cash payouts. Cash flows one way only: advertisers can add cash to amplify, which converts to Credits.
Disclosure
Every ad must be clearly labeled as sponsored. The publisher SDKs handle this automatically — the disclosure label is part of the rendered output. Hiding it is a policy violation.
The Promote loop
Host ads → earn Credits → spend Credits to promote your own product → reach more users → grow the audience that hosts more ads. The whole cycle runs inside BB on Credits; no money ever leaves the platform.

Authentication

Boost Boss uses JWT bearer tokens. Sign in via /api/auth?action=login with your email and password; the response includes session.access_token. Pass it on every subsequent request:

Authorization: Bearer <your-jwt>

Tokens expire — re-call login when you get a 401. The token format is a standard signed JWT, not an opaque API key; you can decode it client-side to read your role and user ID without making a network call.

One special case uses a shared secret instead of user JWTs:

  • OpenRTB BBX (/api/rtb) — DSPs use a seat key issued at integration time, sent as Authorization: Bearer bb_seat_<key>.

Environments

One base URL: https://boostboss.ai. There's no separate api. subdomain. Two modes:

ModeHow it engagesNotes
Demo / in-memoryDefault when Supabase env vars are not setNo real spend, no real Credits minted. Useful for SDK integration smoke tests against a self-hosted clone.
ProductionThe live boostboss.ai deploymentReal auctions, real spend, real Credits. The only mode that issues real bb_session_token JWTs.
